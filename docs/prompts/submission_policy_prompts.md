# 提交策略专项约束

## 1. 提交策略约束

> 本文档是针对操作本仓库的 AI 代理的**提交策略专项约束**。
> 涉及提交、待提交记录维护或 commit 执行时，**必须**完整读取并严格遵守以下全部规则。
> 除非明确说明，否则 AI **禁止**修改本文档。

---

### 1.1 禁止主动提交

- 除非用户提示词中**明确说明**需要提交改动，否则**禁止**创建或推送 commit。
- 在未收到明确请求时，**仅允许**修改文件和添加待提交记录。
- 若任务涉及 `docs/wpf-migration-progress.md` 的 `3.1` 维护，**必须**同时遵守 `docs/prompts/document_special_prompts.md` 的 `§1.4`。

### 1.2 提交执行流程

当用户明确要求提交时，按以下顺序执行：

1. **前置检查**：执行全量回归测试（`dotnet/tests/` 下所有测试项目），结果必须全部通过。如果测试失败，提示用户并停止执行，**禁止**直接进入修复作业。
2. **文件内容检查**：不进行任何文件内容检查以及修改文件内容，直接按照当前状态提交。所有非 AI 提交的变更默认是用户的合理修改。
3. **暂存**：`git add .`（默认提交工作区**全部改动**，除非用户明确指定范围）。
4. **提交**：`git commit -m "<Summary>" -m "<Description>"`
   - Summary 和 Description 必须来自章节 `3.1` 中状态为 `待提交` 的记录。
   - Description 中的 `<br>` 必须替换为实际换行，删除空行，确保每个序号独占一行。
   - 若遇到序号错误，**必须**修正序号。
   - 从输出中记录 7 位短 SHA（如 `0b7644c`）。
5. **回填**：提交成功后立即更新章节 `3.1`：
   - `状态`：`待提交` → `已提交`
   - `Commit SHA`：`-` → 实际 7 位短 SHA
   - 回填改动本身**不做单独 commit**（见 `§1.3`），自然并入下一次代码提交。

### 1.3 禁止单独提交明细

如果唯一的改动是 `docs/wpf-migration-progress.md` 中章节 `3.1` 的提交明细更新，**禁止**将其作为独立提交；**必须**与后续的代码改动一同提交。
