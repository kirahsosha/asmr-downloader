# AI 执行约束

> 以下规则对所有操作本仓库的 AI 代理具有**强制约束力**。在进行任何分析或文件修改之前，必须完整阅读并严格遵守。

---

## 1. 任务规划约束

- **必须**在开始任何非平凡任务时生成详细的 todo list。
- **必须**严格按照 todo list 的操作步骤执行。
- **必须**在任务进展发生变化时，及时更新 todo list 的执行状态。

## 2. 上下文排除约束

以下文件的文本**禁止**加载到分析上下文中，且**禁止**进行任何修改：

- `docs/prompts.md`
- `legacy-go.md`

## 3. `docs/wpf-migration-progress.md` 文件操作约束

对该文件进行任何操作时，必须遵守以下子规则：

### 3.1 上下文范围

- **禁止**将章节 **1.5.1 至 1.5.64** 的文本加载到分析上下文中。

### 3.2 维护检查

- **必须**检查章节 **1.2** 是否需要更新。
- **必须**检查章节 **1.3** 是否需要更新。
- **必须**检查章节 **1.4** 是否需要更新。
- **必须**检查章节 **2.1** 是否需要更新。

### 3.3 变更记录（章节 1.5）

- **仅允许**追加新的变更记录。
- **禁止**修改已有的历史记录。
- 所有更新**必须**符合章节 **1.6** 中定义的维护规则。

### 3.4 提交明细（章节 3.1）

- 如果存在待提交记录，**必须**将其合并为单一条目，并整理精简 Summary 和 Description。
- 如果不存在待提交记录，**必须**新增一条。
- 创建 commit 时，**必须**严格遵循该章节中写明的 Summary 和 Description。

### 3.5 测试清单（章节 4）

- 在进行任何功能开发、缺陷修复或可能影响用户可见行为的改动之前，**必须**先检查本章。
- **必须**将受影响的测试项重置为未勾选状态，并添加新的必要验证项目。
- **仅允许**添加新的未勾选项目，或取消勾选需要重新测试的项目。
- **禁止**勾选任何测试项；勾选操作仅由人类用户执行。

## 4. 提交策略约束

- 除非用户提示词中**明确说明**需要提交改动，否则**禁止**创建或推送 commit。
- 在未收到明确提交请求时，**仅允许**修改文件和添加待提交记录。
- 在创建commit时，如果用户提示词中没有**明确说明**提交范围，默认提交工作区**全部改动**。
- 在创建commit时，删除Description中存在的空行，每个序号一行。
- 如果唯一的改动是 `docs/wpf-migration-progress.md` 中章节 3.1 的提交明细更新，**禁止**将其作为独立提交；**必须**与后续的代码改动一同提交。
